  **==签名==** Signature
  
  **两个层面的"签名"别混
- 代码层的方法签名：就C# 方法形状（这是改代码时直接碰到的）。
- HTTP 接口层的签名：后端那个 API 端点的形状——URL 路径、请求/响应的 JSON 字段。后端改了 HTTP 契约，最终也会反映成"客户端方法签名 + DTO"要跟着变。
  **方法签名** = 一个方法"怎么被调用"的形状，包括：
- 方法名
- 参数的个数、类型、顺序
- 返回值类型
- （有时还含泛型、抛出的异常等）

它是调用方和被调用方之间的契约。

  "签名变更"就是上面任意一项变了
   **为什么"签名变更"是痛点**
因为编译器要求每一个调用点都得跟签名对得上。签名一变，所有调用它的地方都得跟着改，否则编译不过。
  
  ==**DTO**== 
  Data Transfer Object（数据传输对象）
它是一个只装数据、没有行为的类，长相和后端 JSON 一一对应，专门用来"跨边界搬数据"（网络 ⇄ 程序）。
  特点：它们用 camelCase 序列化/反序列化和服务器通信 → 形状由后端契约决定，后端一改，它们就得改。
  
==**领域模型（Domain Model）**==
领域模型 = 你自己 App 内部对概念的表示，由"你的 UI/**游戏需要什么**"决定，和后端线格式无关。
`public enum SpeakerKind { Player, Npc, Narrator }`
`public sealed class ChatLine       // 领域模型：UI 只认它`
`{`
    `public string Speaker;`
    `public string Text;`
    `public SpeakerKind Kind;`
    `public DateTime Time;`
`}`

adapter，适配器是可替换的具体实现（与接口port是一对搭档，接口是抽象）

**==SSE==**
Server-Sent Events（服务器发送事件）
是一个 Web 标准：客户端发起一个普通 HTTP 请求，服务器不一次性返回就关闭，而是把连接保持打开，然后随着数据产生，一条一条地持续推给客户端，直到结束。
 **核心特征**:
- 单向：只有 服务器 → 客户端 的推送（这点和 WebSocket 不同，WebSocket 是双向）。
- 基于普通 HTTP：`Content-Type: text/event-stream`，数据就是一行行 `data: {...}`，不需要特殊协议。
- 一次请求、多次响应：一个请求换来一串陆续到达的事件，而不是"发一次拿一坨"。

对比一下：

|方式|形态|场景|
|---|---|---|
|普通 HTTP 请求|发一次 → 回一坨 → 结束|登录、查列表|
|SSE|发一次 → 服务器流式回 N 条 → 结束|LLM 逐字/逐句输出、进度推送|
|WebSocket|双向长连接|实时聊天室、多人同步|
