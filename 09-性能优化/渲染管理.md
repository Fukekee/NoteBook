## 加载进内存 ≠ 渲染

| 阶段           | 决定因素      | 说明                                                   |
| ------------ | --------- | ---------------------------------------------------- |
| 进内存（Load）    | 场景加载      | 场景里所有 GameObject、Mesh、贴图、材质，在 `LoadScene` 时基本都被加载到内存 |
| 是否渲染（Render） | 相机 + 视锥剔除 | 每帧判断物体在不在相机视野里，决定要不要画它                               |
## 相机做的事叫「剔除（Culling）」，不卸内存

相机范围相关的机制主要有两个，它们都只影响渲染，不影响内存：

1. 视锥剔除（Frustum Culling） Unity 自动做。物体不在相机视锥内 → 这帧不提交渲染。但 Mesh/贴图还在内存。
    
2. 遮挡剔除（Occlusion Culling） 被别的物体完全挡住的，也不渲染。同样不卸内存（需要烘焙）。
    
3. Camera 的 Far Clip Plane / Layer Culling Distance 超出远裁剪面的不渲染。还是不卸内存。
    

一句话：剔除只是“这帧别画”，数据照样躺在内存里。

## 什么情况下才“只加载需要的、不需要的不进内存”

如果你的目标是大场景省内存（只让附近的进内存，远的不进/卸载），那要用主动的**资源管理**方案，Unity 不会自动帮你做：

| 方案                      | 作用                                                                             |
| ----------------------- | ------------------------------------------------------------------------------ |
| 场景分块 + 多场景加载            | 用 `SceneManager.LoadSceneAsync(Additive)` / `UnloadSceneAsync`，玩家走到哪加载哪块，离开就卸载 |
| Addressables            | 按需异步加载/释放资源，用引用计数管理内存，是目前官方推荐的大世界方案                                            |
| 流式加载 Streaming          | 自己写距离判断，动态 Instantiate / Destroy 或对象池                                          |
| Terrain / Tree / Detail | 地形系统有自己的 LOD 和分块加载机制                                                           |
| LOD Group               | 注意：LOD 只切换渲染用哪级模型，所有 LOD 级别的 Mesh 默认还是都在内存                                     |
