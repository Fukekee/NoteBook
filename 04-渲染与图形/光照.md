### 1. 光源类型与 Mode 设置

Unity 中所有 Light 组件都有 Mode 属性：

| Mode     | 行为                      | 性能消耗 | 适用场景             |
| -------- | ----------------------- | ---- | ---------------- |
| Realtime | 每帧实时计算直接光和阴影，不烘焙、无间接光反弹 | 较高   | 动态变化的光（手电筒、闪烁的灯） |
| Mixed    | 静态物体烘焙、动态物体实时；混合工作      | 中等   | 主光源（太阳光）         |
| Baked    | 完全烘焙到 Lightmap，运行时零光照计算 | 最低   | 装饰光、不变的场景光       |

### 2. 各光源类型支持情况

|光源|Built-in|URP|HDRP|
|---|---|---|---|
|Directional Light|全部 Mode|全部 Mode|全部 Mode|
|Point Light|全部 Mode|全部 Mode|全部 Mode|
|Spot Light|全部 Mode|全部 Mode|全部 Mode|
|Area Light|仅 Baked|仅 Baked（新版部分支持实时）|支持实时|

→ Area Light 物理面光源计算很贵，所以传统管线选择只烘焙它。

### 3. 静态 vs 动态物体

要让物体能"接收烘焙光照"：

GameObject → Static 下拉 → 至少勾选 Contribute GI

（旧版叫 Lightmap Static）

- 静态物体：参与烘焙，运行时不能移动，光照信息存在 Lightmap 里。
- 动态物体：不参与烘焙，需要通过 Light Probe 接收环境光信息。

### 4. 烘焙流程

1. 把不动的物体标记为 Contribute GI

2. 摆好场景中所有光源，设置 Mode 为 Mixed 或 Baked

3. Window → Rendering → Lighting → 创建/选择 Lighting Settings

4. 设置 Lightmapper（Progressive CPU/GPU）、分辨率等

5. 点击 Generate Lighting

6. 等待烘焙完成，生成 Lightmap 贴图和 Lighting Data Asset

### 5. Mixed 模式的 Lighting Mode 子设置

这个是大家最容易忽略的细节，在 Lighting Settings → Mixed Lighting → Lighting Mode：

|子模式|直接光|间接光|阴影|备注|
|---|---|---|---|---|
|Baked Indirect|实时|烘焙|实时（远处会消失）|平衡画质和性能|
|Shadowmask|实时|烘焙|近实时 / 远烘焙|推荐，画质最好|
|Subtractive|烘焙|烘焙|烘焙 + 一个实时方向光阴影|移动端低端方案|

### 6. Light Probe（光照探针）

作用：让动态物体在烘焙的场景中也能接收到合理的间接光和环境光。

工作原理：

- 在场景中布置 Probe 点，每个点烘焙时采样此处的光照（球谐函数表示）。
- 动态物体根据所在位置，从最近的 4 个 Probe 做四面体插值，得到当前位置的光照。

使用步骤：

1. GameObject → Light → Light Probe Group

2. 进入 Edit Light Probes 模式

3. 在动态物体可能经过的关键位置摆放探针

（重点：明暗交界处、空间转折处多布点；空旷大平面不需要太密）

4. 烘焙时会自动计算每个探针的光照数据

注意：

- 探针组要包围所有动态物体可能进入的区域，否则边界外会用最近探针的值（可能错误）。
- 探针不影响静态物体（静态物体用 Lightmap）。

### 7. Reflection Probe（反射探针）—— 补充知识

- 与 Light Probe 配套，处理镜面反射。
- 烘焙周围环境到一张 Cubemap，给金属/光滑表面提供反射。
- 也分 Realtime / Baked / Custom 三种模式。

### 8. Emission自发光材质

自发光实际上是两件事：

### 1. 材质本身"看起来亮"（视觉发光）

- 这部分是 Shader 在片元着色时直接输出颜色，不依赖任何光照系统。
- 哪怕你关掉所有光、关闭 GI，物体表面也会"亮起来"。
- 但是注意：它只是自己亮，不会照亮别人。

### 2. 照亮周围的物体（实际产生光照）

- 这部分才需要 GI（全局光照）参与。
- Unity 把 Emissive 材质当作一种**"面光源"**计算，把它发出的光"烘焙"到周围静态物体的 Lightmap 或 Light Probe 里。
- 因此周围的物体才能真正"被它照亮"。
### 9. 完整光照系统知识图

光照系统

├── 直接光照

│ ├── Realtime Light（实时光）

│ │ └── 每帧 GPU 计算，无反弹光

│ ├── Mixed Light（混合光）

│ │ └── 直接光实时 + 间接光烘焙

│ └── Baked Light（烘焙光）

│ └── 全部预计算，运行时零开销

│

├── 间接光照（GI 全局光照）

│ ├── 烘焙到 Lightmap（给静态物体）

│ └── 烘焙到 Light Probe（给动态物体）

│

├── 自发光

│ └── Emissive 材质（需要 Bake 才会照亮周围）

│

├── 环境光

│ └── Environment Lighting（Skybox / 颜色 / Gradient）

│

└── 反射

└── Reflection Probe（烘焙环境 Cubemap）
