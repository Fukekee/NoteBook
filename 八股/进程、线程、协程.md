## 进程：一次运行的播放器

一个 Editor、[^1]一次打出来的 Player、一台 headless 房间服，各自是一个进程。一份[[堆]]、一套场景、一套物理。进程没了，这一局全没。

手机客户端几乎不会再自己开进程。进程出现在运维上：独立服务器、一房间一进程——房间崩了不拖死别的房间。玩法脚本里不用、[^2]也不该 `fork`。(房间隔离如果做成「一台 headless 再开一个进程」，那是运维/启动器的事，不是 `PlayerSetup`这种玩法脚本里写的东西。)

## 线程：主线程几乎包办一切

Unity 里真正天天打交道的是主线程。`PlayerLoop` 不是另一条线程，是这条主线程每帧的行程单：输入 → 物理 → `Update` / 协程 → `LateUpdate` → 渲染 → 网络回调。

60fps 时一帧大约 16.6ms，全挤在这条线程上。`Transform`、`GameObject`、UI、大多数 NGO 回调，都只能在这里碰。

工作线程（[[Task.Run]]、原生插件、Job System）只能算数或做堵住的 IO。算完必须回到主线程再改物体。在后台线程里改 `Transform` 会坏。你们 `Scripts` 里基本没有 Job System。

==线程锁==是一把「同时只准一个人进这扇门」的门闩。 几条线程都要改同一块内存时，用它保证同一时刻只有一条线程在改，避免改到一半被别人插进来，数据花掉。

#### 为什么要有它

要锁的时候是「主线程和工作线程同时碰同一份数据」，例如：

- `Task.Run` 在算，主线程同时在读这份数组
- 共享服务器上，网络线程往房间字典里塞人，逻辑线程同时在结算比分
## 协程：主线程上可暂停的一段脚本

`StartCoroutine` + `IEnumerator`。碰到 `yield return` 就暂停，人还是主线程，只是这一帧不再点你的名字，去跑别人的 `Update` 和渲染。

它不会并行、不会用满多核。等的是「下一帧 / 一秒 / 某个 bool / `UnityWebRequest`」，不是另雇一条线程站着等。

主线程里写死循环或同步读大文件，协程和画面一起停。
