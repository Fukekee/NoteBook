# 一、分模块的思路

**黄金原则：高内聚，低耦合**
   |
- 高内聚：模块内部关系紧密。一个模块里的东西，都是为了同一件事服务
- 低耦合：模块之间联系稀疏。改 A 模块，尽量不牵动 B 模块
## 切分模块的 5 种常用维度

### 1. 按职责（最重要）— 单一职责

一个模块只为一个变化原因负责。（场景管理、人物移动算变化原因）
### 2. 按业务领域

把同一业务的东西聚在一起
AR业务（包含AR的多个类）、地图业务（包含地图的多个类）
### 3. 按变化频率

经常变的和很少变的分开。

|例子|分法|
|---|---|
|关卡玩法（常调数值/规则）|单独模块，甚至放 ScriptableObject 配置|
|网络底层、定位底层（稳定）|独立、少改动的模块|

好处：改玩法时不碰底层，降低出 bug 的范围。
### 4. 按稳定性/依赖方向

稳定的模块不应该依赖易变的模块（依赖要指向稳定的一方）。

`UI 层易变——业务层较稳——基础设施最稳`

UI 可以依赖业务，业务不该反过来依赖具体某个 UI。

### 5. 按生命周期

随场景销毁的 vs 全局常驻的，分开。

|模块|生命周期选择|
|---|---|
|`BackendManager`|DontDestroyOnLoad，全局常驻|
|`StoryProgressManager`|挂 main 场景，不用 DDOL|
|`ARChallengeService`|挂 Arena 场景|
# 二、降耦合的思路

耦合 = 模块之间的「牵连程度」。降耦合就是减少 A 知道 B 多少细节。

## 耦合从重到轻的光谱

最重：直接 new 具体类 / 改对方字段依赖具体类引用依赖接口/抽象通过事件/回调通信最轻：完全不知道对方存在

越往下，越松，越好替换、好测试。

## 5 个最实用的降耦合手段

### 1. 依赖抽象，不依赖具体（前面聊过）

// ❌ 紧耦合：写死具体类

private CircleRegionMatcher _matcher;

// ✅ 松耦合：只依赖能力

private IRegionMatcher _matcher;

你项目里 `RoomValidationServer` 拿的就是 `IRegionMatcher`，所以换实现不影响它。

### 2. 用事件/回调，而不是互相直接调用

让"被依赖方"不知道"谁在用它"。

// ❌ StoryManager 直接调 UI：StoryManager 必须知道 UI 长啥样

storyUI.ShowEnterButton();

// ✅ StoryManager 只发事件：它不知道谁在听

public event Action OnActAvailable;

// UI 自己订阅：OnActAvailable += ShowEnterButton;

好处：以后加「音效提示」「震动提示」，不用改 StoryManager,新模块自己订阅即可。

### 3. 单向依赖，杜绝双向

A → B 可以，但避免 A ↔ B。

双向依赖（互相持有引用）会导致：改一个必须改另一个、无法单独测试、初始化顺序死锁。

解法：把双向关系改成「下层发事件，上层订阅」的单向。

### 4. 委托职责，而不是什么都自己干

`ARChallengeService` 把场景加载委托给 `AdditiveSceneController`，就是这招——不自己 `LoadSceneAsync`，避免和场景管理耦合。

### 5. 通过数据/配置解耦（ScriptableObject）

把「规则、数值、关卡数据」抽成数据资产，逻辑模块只读数据。

你项目里 `StoryChapterData[]`、`ARItemLibrary`、`PuzzleData` 都是这种思路：逻辑和数据分离，改数据不改代码。

==技巧：==
做一个新功能，要问的问题：
1. 这功能有几个不同的变化原因?
2. 按原因拆成几个模块
3. 画依赖方向: 谁依赖谁?
4. 有没有双向依赖? 有就用事件打断
5. 跨模块的地方, 能不能只依赖接口?
6. 哪些是数据? 抽成配置
## 配套的「坏味道」检查清单

看到下面这些信号，就该警觉耦合过重 / 划分不当：

|坏味道|说明|多半该做|
|---|---|---|
|改 A 总要顺手改 B|边界没切对|重新划职责|
|一个类超过 500 行、什么都管|上帝类，内聚低|拆模块|
|到处 `FindObjectOfType<具体类>`|散乱的紧耦合|抽象 + 注入/Bootstrap|
|A 调 B，B 又回头调 A|双向依赖|改单向 + 事件|
|改个数值要动代码重新编译|数据和逻辑混在一起|抽 ScriptableObject|
|加个新功能要复制粘贴一堆引用|缺 Bootstrap/抽象|统一装配|
