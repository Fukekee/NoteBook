# 小游戏效果与 APK 的差异

> 同一份 Unity 工程，导出安卓 APK 表现正常，转成微信小游戏（WebGL / 微信小游戏运行时）后经常出现「跑起来不一样」的问题。这里记录踩过的坑和对应的解决办法。
> 核心原因：微信小游戏底层是 WebGL + 微信自己的运行时，很多在原生安卓上「默认能用」的东西（旋转、压缩纹理、渲染管线特性、分辨率）在小游戏里行为不同，需要走微信 SDK 或做平台分支。

---

## 图片显示全黑或五彩黑

**现象**
- 部分精灵 / 场景美术在 APK 里正常，进小游戏后整块变**纯黑**，或者出现**花屏、五彩噪点（未初始化的显存）**。

**原因**
- 项目里大量素材用的是 **Sprite-Lit（2D 受光材质）**。受光材质的显示 = `贴图 × 光照`，**没有 2D 光照就会是黑的**。安卓上可能因为渲染管线/默认光照兜底看起来还行，但小游戏的 URP 2D 渲染路径更严格，缺 `Light 2D` 就直接黑掉。
- 「五彩黑 / 花屏」多半是**纹理压缩格式或纹理内存**问题：WebGL 平台对压缩格式（ASTC / ETC / crunch）支持和安卓不一致，格式不被支持或解码失败时，就会显示成未初始化的彩色噪点。

**解决办法**
- 不需要动态光照的素材（UI、纯平面美术、已经画好明暗的贴图）**改用 `Sprite-Unlit`**，避免依赖 2D 灯光。
- 确实需要受光的场景，保证场景里有 **Global Light 2D（全局光）** 兜底，再叠局部光。
- 纹理导入设置针对小游戏单独检查：
  - 关掉不必要的 **Mipmap**（尤其 UI）。
  - 压缩格式选 WebGL 明确支持的（谨慎用 crunch），有问题时先退回不压缩 / RGBA32 排查是不是格式导致。
- 排查步骤：先把可疑素材临时切 `Sprite-Unlit` + 不压缩，若恢复正常，再逐项收窄是「缺光」还是「压缩格式」。

## 定时跳跃出现问题

**现象**
- 开场 / 演示里的**定时自动跳跃**，在 APK 里正常，进小游戏后经常**不跳**，或跳的时机、落点和编辑器里对不上。

**原因**
- 旧逻辑用的是 `ForceJump`：**必须落地才能触发**，而且计时走 `Update`（按帧计时）。
- 小游戏端帧率不稳 / 有卡顿时：到「该跳的那一帧」人物可能还没落地，这次跳跃就被**丢弃并记成「已经跳过」**，后面不会再补，于是表现为「没跳」。
- 按帧计时还会导致触发点的位置随帧率漂移，和编辑器里对不上。

**解决办法**
- 计时改到 **`FixedUpdate`，按物理时间计时**，和人物移动同步，不再受帧率和卡顿影响；到点时的位置在小游戏和编辑器里应一致。
- 演示跳跃改成专用的 **`TryScriptedJump`**（不动关卡里正常跳跃的逻辑）：
  - 到点时**当场重新检测一次是否落地**。
  - 若刚好没落地，在接下来 **0.3 秒内等落地再跳**，超时才放弃。
  - 这一帧没跳成（比如还在冷却）**不把这个时间点划掉**，下一帧继续尝试。
  - 起跳力度与原 `ForceJump` 相同，跳多高、跳多远保持不变。

## 屏幕方向切换的问题

**现象**
- 用 `Screen.orientation` 强制横 / 竖屏，在 APK 里生效，进小游戏后**完全不转屏**。
- 即使勉强横过来，画面还在用**竖屏的分辨率**，出现拉伸 / 黑边 / 布局错位。

**原因**
- 微信小游戏运行时里 **`Screen.orientation` 不会生效**，转屏必须走微信自己的接口。
- 转屏和分辨率是两件事：方向切了，但 Unity 侧没有按新的窗口尺寸重设分辨率，画面还是旧的横竖比。

**解决办法**
- 转屏统一走微信 SDK 的 **`WX.SetDeviceOrientation`**：
  - 进关卡传 `landscape`（横屏）。
  - 回主界面 / 进作坊传 `portrait`（竖屏）。
- `LevelManager.SetOrientation` **按平台分支处理**：
  - **编辑器**：只打日志，Game 视图不真的转（避免误导）。
  - **微信包**：调用 `WX.SetDeviceOrientation`，失败时打日志便于定位。
- 分辨率适配：**监听窗口尺寸变化**，尺寸变了之后**按真实横 / 竖屏重新设置分辨率**，而不是沿用竖屏分辨率。
