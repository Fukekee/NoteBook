程序内存里常见两块：

- 栈（stack）：函数里的局部变量，进函数就有、退函数就没，很小很快。
- 堆（heap）：`new` 出来的对象住在这里——`GameObject`、列表、字符串、你们的组件实例。活得更久，要垃圾回收（GC）。

「一个进程一份托管堆」的意思是：这个 Player 进程自己的那片对象内存。进程没了，这片堆一起没，场景、脚本对象全没。不是「把游戏状态复制一份存下来」。

Unity 里还有引擎自己的原生内存（网格、贴图），和 C# 托管堆是两套，但你先按「`new` 出来的东西在堆上」记就行。


「在堆上」说的是这块内存归谁、活多久，不是说你有没有亲手写 `new`。 加载进来的场景里的物体，和运行时 `Instantiate` 出来的，对内存来说是同一类东西。

磁盘上的场景文件main.unity不算堆上的对象。加载之后，场景里被创建出来的那些 GameObject / 组件，才算。 和运行时 `Instantiate` 是同一类，只是创建的人换成了 `LoadScene`。

## 「`new` 在堆上」到底在说什么

C# 里对象有两种住法：

`void Foo()`

`{`

`int x = 3; // 值类型，跟着函数活在栈上，Foo 结束就没了`

`var list = new List<int>(); // 引用类型，盒子在堆上(因为新建了列表在内存中，所以这个列表盒子活在堆上）；list 只是栈上的「门牌号」`

`}`

- 栈： 函数的临时桌面，退栈就收走。
- 堆： 一块公共仓库。`new` 是「在仓库里开一个箱子，给你门牌号」。箱子一直在，直到没人再拿着这个门牌号，GC 才收。

所以「`new` 出来的在堆上」= 这个对象的本体在托管堆里，变量里存的是地址。

Unity 里你很少手写 `new GameObject`，但引擎替你做的是同一件事：在内存里创建实例。

unload场景的话，该场景有关的实例就会从堆上消失

additive加载就是在堆上加一份实例
