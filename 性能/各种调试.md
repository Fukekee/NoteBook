## 推荐怎么调试（先不改业务代码）

 `Debug.Log("pos=" + …)`可以用，但不要过度，因为它会加重编译器的负担

按“不动代码 → 少动代码 → 最后才长期打日志”排。

### 1. 调试器：比普通断点更有用的几招

|手段|做什么|
|---|---|
|Logpoint / Tracepoint|断点改成“不暂停，只打印”。表达式里写 `gb.transform.position`，不改源码、不装箱进你的热路径（开销在调试器侧，且可设条件）|
|条件断点|例如 `position.y < 0` 或 `Time.frameCount % 30 == 0` 才停|
|Hit count|第 N 次、每 N 次停一次，避免每帧断死|
|Watch / Locals|停住后看 `transform.position`，结构体直接显示，无 Log|
|Immediate / 调试控制台|暂停后求值 `gb.transform.position`|
|单步 + 帧步进|看完这一帧再 Continue|

Cursor / VS / Rider 挂 Unity Editor 后都能用。这是“除了改代码、除了普通断点”里我最推荐的。

### 2. Unity 里不靠字符串的看数据

- Pause 后看 Inspector：点物体，开 Inspector 右上角 Debug 模式，能看私有字段。
- `Debug.DrawLine` / `Debug.DrawRay`：看位置、朝向、射线，Scene 视图里画，无字符串、无 Console。
- `OnDrawGizmos` / `OnDrawGizmosSelected`：画包围盒、锚点、寻路点。只在 Scene 里画，不进 `Update` 日志。
- Frame Debugger：看某一帧谁在画、为什么看不见。
- Profiler：CPU / GC Alloc。怀疑装箱就看 `GC.Alloc`，点进 `Update` 看是不是 Log。
- Physics Debugger / Animation 窗口：碰碰撞、动画用专用窗，别打 Log。

位置类问题：Gizmos / DrawRay 通常比 `Debug.Log(pos)` 清楚。

### 3. 必须打日志时怎么打

- 不要放进每帧：用按键开关、或 `frameCount % 30 == 0`。
- 需要时再开：`#if UNITY_EDITOR`，或一个 Inspector 上的 `enableDebugLog`。
- 少拼接：`Debug.Log(position.ToString())` 仍分配，但比每帧无节流好。
- 多个数用你们已有的调试 UI（例如 `LocationDebugUI` 改已有 Text），比 Console 刷屏便宜、也好看。
