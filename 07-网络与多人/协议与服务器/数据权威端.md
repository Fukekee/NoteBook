## 服务端权威（Server Authoritative）

对于任何需要**防作弊、需要跨设备同步、需要持久化保存**的进度数据，服务端必须是唯一的权威来源（Single Source of Truth）。

原因：

1. **防作弊/防篡改：** 本地数据在玩家自己的机器上，可以被内存修改器、存档修改、抓包改包等方式随意篡改。如果以本地为准，玩家可以直接把剧情进度改成"全部通关"、解锁付费剧情、跳过条件。
2. **跨设备/多端一致：** 换手机、重装、网页端和客户端切换时，进度得以服务端为准才能同步。
3. **数据安全：** 本地存档容易丢失（卸载、清缓存、换机），服务端存储更可靠。
4. **运营需求：** 发放奖励、活动条件判定、数据统计都依赖服务端可信数据。

## 什么该由服务端权威

- 主线/支线剧情节点的解锁状态
- 关卡/章节完成进度
- 付费内容、道具、货币
- 成就、任务完成判定
- 任何"给奖励""解锁内容"的判定

关键点：不是让客户端告诉服务端"我完成了第 5 章"，而是客户端上报行为/请求，由服务端校验条件后自己推进进度。客户端只是发起请求和展示结果的一方，不能直接决定结果。

## 本地（客户端）适合做什么

本地不是完全没用，它承担这些职责：

- 表现层状态：当前对话播到第几句、动画/演出进度、UI 状态——这些纯表现的东西以本地为准没问题。
- 预测/即时反馈：为了流畅体验，客户端可以先本地表现（乐观更新 Optimistic Update），再等服务端确认，冲突时以服务端回滚。
- 离线缓存：断线时本地先记录，联网后提交给服务端校验合并，而不是直接覆盖。
- 纯单机部分：如果某段剧情完全单机、不涉及奖励和付费，可以本地为主，联网时再上报。

## 常见的折中/权衡

| 场景                       | 权威方      | 说明                        |
| ------------------------ | -------- | ------------------------- |
| 强联网游戏（MMO、竞技、卡牌）         | 服务端      | 几乎全部服务端说了算                |
| 弱联网/单机+云存档（很多手游、买断制剧情游戏） | 本地为主，云同步 | 本地推进，定期上传；冲突时按时间戳/进度较大者合并 |
| 完全单机                     | 本地       | 无服务端                      |
