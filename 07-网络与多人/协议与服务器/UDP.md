### 1. 基本概念

- 一台服务器可以同时使用多个端口。
- 端口按协议区分：`TCP:7777` 和 `UDP:7777` 是两条独立通道。
- 不同端口可以处理不同业务。

### 2. TCP 和 UDP 区别

- TCP
    - 面向连接、可靠、有序、不丢包（应用层视角）
    - 适合请求-响应、配置下发、状态确认
    - 延迟通常更高，可能有“队头阻塞”
- UDP
    - 无连接、低延迟、允许丢包/乱序
    - 适合实时同步（位置、动作、状态）
    - 需要应用层做插值、重传或容错

### 3. 项目中的对应关系

- `TCP 7350`：房间管理通道
    - 建房 `create`
    - 设置时长 `set_duration`
    - 返回 `roomCode / serverIp / gamePort`
- `UDP 7777`：游戏实时通道（NGO/Unity Transport）
    - 玩家位置同步
    - RPC / NetworkVariable 同步
    - 实时联机数据

### 4. 为什么混合使用（TCP+UDP）

- 控制类消息要可靠 → 用 TCP
- 实时类消息要低延迟 → 用 UDP
- 全 TCP 会实时体验差；全 UDP 会让管理逻辑复杂化

### 5. 部署时必查项

- 安全组/防火墙要分别放行：
    - `TCP 7350`
    - `UDP 7777`
- 只放行 TCP 不等于 UDP 也通。
- 客户端“卡在连接中”常见原因：UDP 端口未放行或服务器未监听 UDP。

### 6. 常见排查思路

1. 先看 TCP 建房日志是否成功（有无 roomCode 返回）。
2. 再看 NGO 客户端是否发起 `StartAsClient(ip:7777)`。
3. 服务器是否有 `StartServer result=True`。
4. 检查 `UDP 7777` 是否开放且正在监听。
5. 检查客户端/服务器 Network Prefabs 列表是否一致（避免握手失败）。

### 7. 一句话总结

- TCP 做“房间管理”，UDP 做“实时联机”。
- 按功能选协议，而不是一个协议包打天下。
